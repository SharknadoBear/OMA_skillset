# FVCOM Namelist Configuration

Turn a scientific scenario into a version-compatible, auditable FVCOM runtime configuration.

## Contract

Read [references/contracts.md](references/contracts.md) before generating a configuration. Use `scripts/fvcom_namelist.py` to make a provisional overlay, render a final namelist from the exact frozen executable's blank template, write cell-based station specifications, and validate physics plus file references.

The authoritative template is generated by the frozen executable on one MPI compute rank with `<executable> --create_namelist=<basename>`. Never invent a missing group or key: rendering must fail if a required field is absent from that template. Normalize the final file to the explicitly configured groups and keys so descriptive placeholder values and binary NULs in the generated blank do not leak into a runnable namelist. A provisional overlay is explicitly non-runnable until joined with this template and complete input bindings.

## Tide-only invariants

- Use FVCOM's three-dimensional runtime layout with `BAROTROPIC=T`; `TWO_D_MODEL` must not be compiled.
- Initialize uniform 20 degC temperature and 30 PSU salinity while `TEMPERATURE_ACTIVE=F` and `SALINITY_ACTIVE=F`. Serialize each constant as a scalar so FVCOM 4.3.1 preserves the second array member's `-99` mode sentinel.
- Require ten uniform sigma levels (nine layers) through the preconfiguration manifest.
- Activate only time-series open-boundary elevation. Disable surface forcing, atmospheric pressure, precipitation/evaporation, rivers, T/S OBC nudging, mean flow, longshore flow, groundwater, waves, particles, sediment, ice, biology, and assimilation.
- Use a two-day ramp for a cold start inside the seven-day spin-up. Convert two days to internal steps using `EXTSTEP_SECONDS * ISPLIT`; hot-start benchmark/production segments have no new ramp.
- Require stage duration, six-minute station/forcing cadence, three-hour grid cadence, and ramp duration to be integer multiples of the internal step. Reject an incompatible schedule before submission; run-control can lower controls to a compatible time quantum without relaxing stability bounds.
- Write stations at cell locations every 360 seconds with elevation and depth-integrated `ua/va`, not 3-D velocity or tracers.
- Give `GRID_EDGE_FILE_NAME` a real attempt-bound filename. FVCOM 4.3.1 writes node-to-element adjacency there when `READ_GRID_EDGE_FROM_FILE=F`; use that mode only for the first cold smoke. Freeze the generated artifact, set `grid_edge_read_from_file=true`, and reuse it for later cold canary/spin-up stages and all hot-start benchmark/production runs whose input bundle is immutable/read-only.
- Write coarse full-grid elevation plus depth-integrated velocity every 10,800 seconds.
- Set `NC_SUBDOMAIN_FILES='FVCOM'` exactly. FVCOM 4.3.1 always passes this value to `SETUP_SUBDOMAINS` when NetCDF output is active; the sentinel is case-sensitive, and values such as `none` are treated as subdomain filenames.
- Write a restart at the end of spin-up. Disable restart output for smoke and canary because their end times precede that epoch and FVCOM rejects a future first-restart time.

## Workflow

1. Validate `simulation_request_v1`, explicit artifact bindings, numerical controls, and stage (`smoke`, `canary`, `spinup`, `benchmark`, `production`, or `full`).
2. During the initial parallel phase, emit a provisional overlay and manifest. It may carry unresolved grid-dependent paths but must already pass the physics audit.
3. After the grid/forcing join, write a station file from model station-to-cell mappings. Station records must include stable station ID, model longitude/latitude, one-based FVCOM element ID, and depth. Under the explicit `containing_cell_or_nearest_wet_cell` water policy, preserve original NOAA coordinates separately and allow outside gauges to use fixed nearest wet-cell centroids; currents remain strictly inside. Native cell elevation is the three-node arithmetic mean, not interpolation at the gauge coordinate.
   Generate the mapping from the exact grid-delivery contract and its matching
   NOAA station inventory with `scripts/prepare_station_mapping.py`
   (`--water-level-mapping-policy`, projected-metre `--metric-crs`, optional
   `--diagnostic-mapping` retaining prior rows). Outside proxy candidates return
   `needs_proxy_review` until `--proxy-review` binds the exact mesh and selected
   station/cell pairs in a passed `fvcom_waterlevel_proxy_review_v1` record.
   Require top-level `metric_crs`; every reviewed row contains `station_id`,
   `cell_id`, exact `observation_longitude/latitude`, `model_longitude/latitude`,
   `node_ids`, `depth_m`, `distance_m`, and `selection_approved=true`.
   Verify the same geometry (1 cm centroid/distance and 0.1 mm mean-depth
   serialization tolerance) so a stale review cannot authorize moved gauges.
   Record basin/coast/depth evidence before agreement statistics; distance alone
   is advisory and never blocks numerical execution with existing diagnostics.
4. Render the exact blank namelist produced by `$fvcom-build`; every changed key must exist in the matching group.
5. For a final package, validate every required file relative to the supplied input root, verify the ten-level preconfiguration manifest, and write the configuration manifest with hashes.
6. Return status `provisional_ready`, `ready`, or `blocked` with explicit warnings, blocking reasons, and resume token. Do not submit jobs.

Preserve all rendered namelists. Stability changes create a new attempt-specific namelist; they never overwrite an earlier attempt.
