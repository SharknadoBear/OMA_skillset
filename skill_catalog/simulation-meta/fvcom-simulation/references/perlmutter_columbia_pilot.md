# Perlmutter Columbia combined smoke

Use the approved Columbia factorial combined member as the scientific reference. The pilot is a separate 24-hour CPU smoke, March 18–19, 2025 UTC. Retain the same mesh, ordered OBC, station/section mappings, barotropic controls, hourly atmosphere and combined boundary, and 19-node discharge package. Its reference is the audited 52-rank Kestrel combined smoke.

Set `execution.site` to `perlmutter`, `execution.stages` to `["smoke"]`, `profile` to `columbia_wind_river_factorial`, and `mode` to `barotropic-tide-wind-river`. Supply one top-level `perlmutter` object. Provide the actual selected NERSC CPU charging account, resolved absolute `project_dir` and `source_dir` in scratch, and the observed native `build_environment`. Keep site paths, account and bridge receipts in the local study. The resolver pins the same FVCOM_MP commit and defaults to a single smoke attempt. The retained science period provides the namelist anchor.

1. Initialize the new project with `fvcom_run_control.py init --request REQUEST --project PROJECT`. This records `execution_site` and `perlmutter_root`.
2. Through `$perlmutter-hpc`, build with the selected Perlmutter CPU programming environment, freeze the native compiler/MPI/NetCDF modules, flags and executable SHA-256, verify pressure/river support and native namelist compatibility. Stage `run/build/executable_reuse_binding.json` with `execution_site: perlmutter`, the executable's absolute Perlmutter path, revision, build environment, digests, and feature definitions. Verify the gridding, forcing and configuration role handoffs against the archived inputs.
3. Materialize `attempt --project PROJECT --grid-case retained_columbia --index 0 --stage smoke --controls CONTROLS --base-input INPUT --base-namelist NML --remote-executable NATIVE_BINARY --case-name columbia --skill-installation RECEIPT`. Invoke `freeze_attempt_inputs.py --project PROJECT --attempt run/retained_columbia/attempts/attempt_smoke_0000`. Transfer both flat inputs and the complete frozen run directory to the selected remote project. The native Slurm script binds its working directory and verifies the executable, namelist and every input immediately before MPI launch.
4. Submit the generated job with one CPU node, 52 MPI ranks, core binding, one thread per rank and a 30-minute debug QoS limit. The launcher selects the frozen CPU module stack and verifies the actual allocation, rank count and runtime digests. Before MPI starts it publishes `launch_identity.json` with the native job ID, rank count and observed executable SHA-256. Include that file and `launch_allocation.txt` in the checked native return. Require the exact native end time, 241 station records, nine three-hour full-grid records, final restart, retained OBC and wet source checks, active atmosphere and discharge readers. Compare the retrieved results with the archived smoke on identical clocks and native wet supports. This stage establishes cross-site execution and numerical agreement at the recorded tolerances.

See [NERSC example CPU jobs](https://docs.nersc.gov/jobs/examples/) and [NERSC queues and charges](https://docs.nersc.gov/jobs/policy/).
